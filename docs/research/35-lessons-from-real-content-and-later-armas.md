# Lessons from real content: official missions, community classics and later Arma titles

Research doc 35 for Plotroom (`ofp-editor`). Research date: 2026-09-27. Audience: contributors and LLM coding agents. This file is meant to be read on its own.
Question answered: what do the shipped CWA content (campaigns, single and multiplayer missions, editor templates, configs), the best community missions and campaigns, and the later Arma titles teach about mission and campaign design, and what should Plotroom's harness (lenses, primer, modules, templates, generator defaults, lints, Standing Orders, campaign designer, strategic layer) do with it so that the out-of-the-box experience is good?

**Status.** Proposal-only. Corpus numbers are measurements; every Plotroom design is **[I]**; every threshold is a placeholder for the balance lab (doc 29 §5.2) or playtests.
**Epistemic legend.** **[V]** verified: a corpus measurement backed by a data file, a pinned engine line (`CWR:` = `BohemiaInteractive/CWR@ffc61838b7:engine/Poseidon/`), a string found in the 1.99 executable, or a fetched web page. **[V-search]** seen only in a search snippet. **[I]** inference or design transfer. **[U]** unresolved.
**Legal and hygiene.** The corpus is the owner's own install, read locally and never committed. This doc holds only our own words, aggregate statistics, command, class and key names with counts, and short structural descriptions. No script, briefing, dialogue, stringtable text or mission file is reproduced. Campaign missions are named by neutral slot ids (P = playable, C = cutscene mission, H = chapter cutscene), not by folder names. Nothing here refers to private or unpublished work.

## TL;DR

- **The corpus is genuine 1.99-era content and it parsed cleanly.** 398 mission folders (313 binarized), 0 parse errors. The legacy folders carry the same date as the 1.99 executable (2016-10-08); Remastered templates differ only in names and localisation; the missions and campaigns of the Cold War Enhanced (CWE) mod are mostly copies of official files [V] (§1).
- **An official SP mission has a narrow, known shape.** Median (p90): 30 (57) groups, 75 (122) units, 68 (135) waypoints, 40.5 (74) triggers, 11.5 (47) markers, exactly 1 playable unit, never more than 12 units in a group, enemy:friendly about 2.3 [V]. → Scale presets, force defaults and an advisory "larger than any official mission" lint (§2, §9).
- **Triggers carry the logic; scripts carry the camera.** 74% of SP triggers are condition-only and 38% exist only to play ambient sound; about 30% of all command uses sit in trigger fields; camera commands are 24% of all uses, and 1,489 capture headers show BI shot its cutscenes in-game [V]. → An ambient-soundscape module, a rule builder that covers trigger idioms first, and doc 32's capture-first cinematics (§2, §4).
- **BI's campaigns are nearly linear with retry-on-lose.** 61 of 83 entries retry themselves on a loss; failures that move the story use END codes, never LOOSE; cutscene nodes route every code forward; BI's ending idiom (flag → short outro → `END<n>` with `forceEnd`, commit in `exit.sqs`) is doc 19's socket design [V] (§3).
- **Persistence was small and targeted in 1985, heavy and brittle in Resistance.** 1985 uses 10 saveVar names in "covert op shapes the next battle" links; Resistance uses about 112 names, per-soldier saveStatus, a weapon pool and a roster with veterancy and capped refills, and ships write-only variables, misspellings and a whole mission cloned to add two tanks [V]. → Typed roster and shaping-op modules, branch output contracts and state lints (§3, §9).
- **A single mission ends in a matrix of outcomes, and a survivable failure is an END code with its own debrief.** No official single mission uses LOOSE, no briefing anywhere defines `Debriefing:Loser`, and 18 of 24 single missions have a reachable failure ending [V]. The primer's "END1–END6 are wins" is wrong (§4, §10).
- **Fairness has concrete recipes**: boundaries that warn before they punish, alarms heard before staggered reaction waves arrive, anti-softlock fallbacks (fleeing, not detected for N s, timeouts), delayed autosaves, fallbacks when the leader dies, and radio calls the player times [V]. Each becomes a module or a default (§4).
- **Official MP is small and idiom-driven**: 30 missions with 3–17 slots, BASE respawn for PvP, one END1 for everyone, a placed game logic as server authority, publicVariable mirrors and two lobby params with 10000 meaning Unlimited. Several respawn and briefing rules fail silently [V]. → The missing multiplayer lens, a primer MP section, MP modules and MP lints (§5).
- **The original "new mission from template" is a parametric generator.** 1–15 draggable `WIZVAR_*` anchors drive 12,034 expression-valued fields in 72 template files (36 templates in each edition): a few bounded spatial choices, and code computes the rest, which is the weak-model shape. It also shows that numeric fields are evaluated as script at load, an untracked evaluation surface [V/I] (§5.8).
- **The 1.99 executable's string table settles most dialect questions.** All 236 command names seen in shipped content are present as strings in `ColdWarAssault.exe`. Of the 273 registered names never seen in content, 142 are present (`isServer`, `createDialog`, `onMapSingleClick`, `while`, `if`, `private`, `benchmark`, …) and 131 absent (`createGroup`, `createTrigger`, `createMarker`, `setMarkerText`, `setDate`, `for`, `exitWith`, `allowDamage`, `endGame`, `remoteExec`, …) [V strings; I availability] (§8).
- **The community added systems, not rewrites.** CWE put behaviour into config event handlers and 20 logic "module" classes, so its big battles need few triggers; the loved classics won on atmosphere, role mechanics, visible consequences and a few randomised key facts; most 2021 MP time went to CTI on a few always-on servers with about 2 humans each [V] (§6).
- **Later Arma titles converge on** hubs with optional sorties, contingencies instead of dependencies, fail-forward finales, a lives economy the host chooses, session generators (half of the Workshop's top 60 scenarios, from only 3 design families), short one-life co-op and visible escalation meters [V/I] (§7).
- **Harness core (§9):** 90 rows: a new multiplayer lens and updates to the existing lenses, primer fixes and an MP section, about 20 new or refined modules, parametric templates, corpus-seeded generator defaults, lints drawn from defects that actually shipped, Standing Orders chapters and Drill moves, campaign-designer defaults and strategic-layer seeds.
- **Corrections (§10)** to docs 03, 04, 05, 12, 18, 19, 23, 24, 25, 26, 27, 29, 31 and the primer; three claims made during this research are also withdrawn there.

### 1.2 Legacy 1.99 against Remastered 3.05

- **Dates.** All legacy content folders share the date of `ColdWarAssault.exe` (1.99). The content itself was authored earlier: some `init.sqs` files still require version 1.30 [V].
- **Templates.** Scripts are byte-identical, and so is every `description.ext` except one SP template whose loading text names a different island. `mission.sqm` differs only in `briefingName` (33–36 of 36), a few marker texts and one position. Remastered moves prose into UTF-8 stringtables (`.utf8.html`, `stringtable.utf8.csv`, Polish and Russian added) and modernises no logic [V].
- **Campaigns.** Remastered's 1985 `description.ext` is identical; Resistance swaps two identity names for stringtable keys. Red Hammer is not installed in any edition [V].
- **Configs.** `CONFIG.BIN` differs by 2 entries (Russian font remaps) and `RESOURCE.BIN` by 51 values (48 layout fixes in the Trigger dialog, 1 in the Waypoint dialog, 2 titles); all 27 addon configs are identical. One catalog model serves both profiles [V].

### 1.3 Method and limits

- **Tools.** Our own local Python scripts (not committed): SQM and `description.ext` parsers, an SQS tokenizer checked against the CWR command registry, a raP v4 reader, and executable string scans. The debinarized `.cpp` files in the corpus had lost every class inheritance link (0 `class X: Base` survive), so all catalog numbers come from the binaries [V].
- **Statistics.** Per group: min, median, p90, max, mean. Friend or foe comes from the Intel `resistanceWest/East` values with a 0.5 threshold, which is an assumption [I].
- **Limits.** Idiom detectors are regex heuristics and give lower bounds. Counts include dead code (developer cheat triggers, unreachable scripts). Observation proves use, never absence. Community sentiment rests mostly on OFPEC reviews, some written by people involved in the missions. The 2021 play data is concentrated on a few servers [I].

### 2.2 Other headline measurements [V]

- **Forces.** About half of SP groups are single units (vehicles, static gunners, sentries); 25% have no waypoints; about 11% patrol on a CYCLE; groups average 2.4 waypoints. Unit entries: Men 80%, Armored 14%, Car 2.3%, Air 0.7%.
- **Waypoints.** 6,583 SP waypoints: MOVE 54%, HOLD 11%, CYCLE 7.8%, SAD 6.4%, AND 6.0%, GETIN 4.9%, GETOUT 3.3%, GUARD 3.1%. All 408 official AND/OR waypoints (402 in SP, 6 in co-op MP) sit in LOGIC groups, and 45% of SP missions use such game-logic gates. 82–89% of waypoints leave behaviour, combat mode and speed unchanged; when set, the usual values are SAFE, RED and LIMITED.
- **Triggers.** 3,725 SP triggers: activation NONE 74%, PRESENT 92%; type NONE 87%, SWITCH 7.2%, END1–6 4.5%, LOOSE 0.6%. 1,426 (38%) only play an ambient sound (a median of 12.5 per mission, up to 69). Area triggers are large: the median of per-mission median radii is 410 m against the 50 m default.
- **Environment.** Median start hour 7; night starts 17% of SP (3% of MP); dawn or dusk 29%; median overcast 0.3 (MP 0.5); fog 0 at the median. Area of operations 3.7 km (p90 7.4 km); player route 2.0 km; a waypoint leg 79 m.
- **Replayability.** Presence probability below 1 and placement radius each appear in 31% of SP missions; presence conditions in 3%; `random` appears in the mission-file expressions of 3.5% of SP missions.
- **Localisation.** Five languages are standard (EN, FR, IT, ES, DE), Czech in 30–45%; an SP stringtable has 20 keys and about 200 English words at the median. CWE ships one language.
- **`description.ext`.** In the 204 official mission and template files: `onLoadMission` 155, `minScore/avgScore/maxScore` 88, `onLoadIntro` 73; classes `CfgSounds` 158, `CfgRadio` 144, `CfgSFX` and `CfgEnvSounds` about 135, a gear pool in 26% of SP. `CfgIdentities` appears in only 1 of those 204 files; identities live at campaign level (15 in 1985, 8 in Resistance).
- **Catalogs** ([`catalog-sizes.csv`](data/catalog-sizes.csv)). 263 public vehicles (West 55, East 40, Resistance 26, Civilian 120 mostly objects), 80 public weapons and 92 magazines; `CfgGroups` has only 8 presets (West and East only); Kolgujev and the desert island have 0 named places; 13 marker icons, 9 colours, 8 brushes; 63 groups per side (9 letters × 7 colours). One "class | name" line per public vehicle costs about 1.7k tokens.

## 3. The official campaigns

### 3.1 Graph shape [V]

- **1985.** 7 chapters, 52 entries: 42 playable nodes (41 per run), 10 cutscene missions, 6 chapter cutscenes, 3 awards, 3 penalties and a game-over at `exitScore` −15. After chapter-level fallback is resolved it branches three times: P06 (END1 leads to a lone-escape mission, the other codes to a different mission; both rejoin), P40 (a launched missile leads to the bad epilogue) and the finale P41 (END1–3 to the good epilogue with a playable civilian coda, END4–6 to the bad one).
- **Resistance.** 3 chapters, 31 entries: 20 playable nodes (18 per run), 11 cutscene nodes, 3 chapter cutscenes, `weaponPool = true`, `exitScore` −100 (effectively off). Branch points: P02 (a moral choice: stay loyal or betray), P03 (a second chance: helping rejoins the main line, a second betrayal leads to an execution cutscene that ends the campaign because a no-groups mission yields `lost` and the chapter's `lost` is empty), P10 (the intel mission: failure leads to a harder copy of the next mission) and the finale split.
- **Entry-level counts.** 61 of 83 entries retry themselves on a loss; 5 of 83 have two or more distinct end targets at entry level (1985's two late splits live in chapter fallbacks) [V; reconciliation I].
- **Routing conventions.** Every playable node except 1985's closing civilian coda (whose `lost` ends the campaign) maps `lost` to itself (LOOSE means retry). Every cutscene node explicitly maps `lost` and all codes to the next node, because an empty mission always ends as `lost`. The last mission of a chapter relies on the chapter fallback. Failures that must move the story use END codes. Only 21 of 42 1985 playables and 2 of 20 Resistance playables contain a LOOSE trigger at all.
- **Unreachable content.** A zero-unit folder holding only an END6 trigger (probably a demo limit) and one Resistance mission that no node references.

### 3.2 Pacing, modes and scale [V]

- **One mode at a time.** 1985 has 4 voiced protagonists, set up once in the campaign's `CfgIdentities` and applied by `setIdentity` on the player in each mission. The infantryman carries P01–P13 alone; then each new mode arrives at low threat: tank in a training mission (P14), special forces (P16, introduced earlier in a cutscene), squad command (P21), pilot on a ferry flight (P29). Tally: infantry 21, special forces 8, tank 6, pilot 6, civilian coda 1. 6 of 8 special-forces missions start between 00:00 and 04:00 with 1–3 men. The last act is one evasion then three special-forces missions.
- **Sawtooth intensity.** Enemy units per mission dip at new modes and right after chapter cutscenes (6–32) and peak at escapes, the armoured push and the finale (93–110); the final act has no valley. Resistance dips to about 30 in its solo intel mission.
- **Time and weather.** Dawn is the most common explicit start in 1985 (14 of 38); about 21% of known weather values are overcast ≥ 0.6. The downed-pilot evasion turns off map, compass and GPS.
- **Scale.** Medians, 1985 against Resistance: groups 30/42, units 74/80, triggers 43/53, waypoints 74/63, markers 12/17, empty objects 17/26, SQS lines 68 (3 files)/227 (4 files). 1985 puts its logic in triggers (about 12 countdown triggers per mission); Resistance is about three times as script-heavy, mostly because of persistence plumbing.
- **Cinematic density.** 1985 has about 15 cinematic nodes for 41 missions played; Resistance about 12 for 18, with longer intros (median 125 s against 87 s). This matches the "lengthy cutscenes" criticism recorded in doc 28 [V/I].

### 3.3 Endings: BI's socket idiom [V]

1. An event trigger sets an ending-index variable (often with `saveVar` and `addRating`) and runs a short outro script.
2. The outro's last line sets a finished flag.
3. `END<n>` triggers test "finished and index = n" and call `forceEnd`.
4. LOOSE triggers wait 4–5 s after a failure flag.

Resistance commits its persistence in `exit.sqs` (19 missions). The engine runs `exit.sqs` once at the end with the end code as `_this` and an unlimited line budget, and not when the player is killed (`CWR:UI/DisplayUIMenus.cpp#L984-L994`). Most missions use one END code (1985: 22 of 42; Resistance: 16 of 21); extra codes mostly grade the result, set state or vary the debrief while routing to the same successor. The 1985 finale's six codes form a 3 × 2 matrix, yet the graph splits only two ways. One mapped code has no trigger.

### 3.4 Persistence [V unless marked]

- **1985: shaping op → decisive op.** 10 `saveVar` names form 4 producer-to-consumer links. Each starts in a special-forces mission and pays off in the next big operation, 3 of 4 times one played by another protagonist: fewer enemy tanks, a gunship present or absent, discovered AA sites shown as targets across a chapter break, and AA vehicles that start damaged.
- **Standalone play.** Consumers guard every campaign variable with a self-comparison "is it defined" test and fall back to defaults, sometimes random ones (69 checks in 21 1985 missions, 21 in 16 Resistance missions).
- **Resistance roster.** The player starts alone; `init` loads saved survivors into about 12 placeholder soldiers and deletes the unused ones, restores two flagged medic slots, adds up to K reinforcements from about 8 spare slots, raises each survivor's skill by 0.2, re-equips everyone from the pool and joins them to the player. K is computed at the previous exit as a per-mission cap (3–10) minus survivors. Losses therefore cost veterancy and gear rather than headcount, a built-in anti-death-spiral rule [I].
- **Resistance state.** About 112 `saveVar` names in 16 missions, prefixed by mission number, so the chain is hard-wired to mission order. Alternative branches write the same names (an output contract). Vehicles persist as position and direction triples; a cutscene deletes vehicles by capture flags so it shows the real outcome. Command totals: `saveStatus` 78, `loadStatus` 55, `fillWeaponsFromPool` 41, other pool commands 108.
- **A difficulty delta by cloning.** The intel mission's failure branch leads to a full copy of the next mission with one more T-72, one more T-80 and no intro, so the persistence code exists twice.
- **Shipped defects.** 22 of the ~112 Resistance variables are written and never read (a vehicle import was abandoned behind an unconditional exit); two exits clamp another mission's variable; one pool-sweep loop has an inverted guard; a 1985 mission misspells a campaign variable twice with two different prefixes, so those branches never fire; one person is defined twice under two spellings; one misspelt key; three missing semicolons the engine tolerates; one reachable ending without a debrief and one with placeholder text. Their effects are inferred from reading [I].
- **Score and awards.** Per-mission points are clamped to −3..+4 from experience against `minScore/avgScore/maxScore` (`CWR:AI/AICenterStats.cpp#L82-L113`). 1985 calibrates every scored mission; Resistance copies one triple into 19 of 26. In the CWR source the award selection starts at `INT_MAX` and tests `limit > best`, so it can never pick an award: the authored reward cutscenes never play, while penalties do (`CWR:UI/OptionsUI.cpp#L1844-L1882`) [V by reading; 1.99 binary U]. `noAward` covers 12 of 42 1985 playables and 8 of 20 in Resistance: scripted defeats, escapes, variants and finales.
- **Rating as a tool.** 1985 grants +200 to +2,000 for finds and successes and −100 for straying; Resistance uses −10,000 and −50,000 (23 uses) to make specific units renegades, and `setCaptive` (84 uses) to keep units from being engaged.
- **Failure is absorbed but invisible.** Resistance carries losses forward in roster and pool, 1985 in a hidden score that can end the campaign; neither shows the player the rule, and doc 28 records players guessing [I].

### 3.5 Craft that made moments [V]

- **Moment recipes.** A scripted reversal (the evacuation vehicles are destroyed by timed damage whatever the player does, and new objectives replace hidden ones), a hidden 30–32 minute doom clock in the finale, music stingers on key kills (89 `playMusic` in 50 1985 missions), named characters dying in cutscenes, a return to the island of an earlier defeat, a combat-free playable epilogue (133 triggers and 244 waypoints of choreography), a peacetime slice-of-life opening before the invasion, skip flags after 90–120 s so no gate can stall, and just-in-time hints (first wound, low ammo).
- **Choice interfaces.** Action-menu entries (`addAction`), radio triggers that let the player time an event, physical choices (which vehicle to take; which edge of the area to leave by) and graded outcomes through several END codes.
- **Briefings.** 59 campaign briefings, no images: a Main section with a date line and the situation (median 91 words), a Plan of about 35 words that says where you start, a median of 4 objectives of about 12 words, about 5 marker links, and debriefs only for reachable codes (median 21 words). Objectives are hidden and revealed at run time (`objStatus` HIDDEN 41 times and ACTIVE 33 times in 1985). The training mission and the first combat mission have no briefing; orders come from an in-engine scene.
- **Dialogue.** Every line is voiced and subtitled (961 line classes in 1985, 685 in Resistance), with a median of 11–15 words (p90 23–33) and essentially no text chat. About 19% of 1985's side-radio lines come from an off-map HQ; Resistance, whose guerrillas have no HQ, speaks face to face. Orders scenes follow one pattern: the speaker talks, listeners watch him, a talk animation plays, a `saveGame` follows. Out-of-area warnings are defined once at campaign level (used by 27 of 41 1985 missions).
- **Checkpoints.** `saveGame` appears in 32 of 42 1985 playables and about half of Resistance's, usually after an orders scene or a phase change.
- **Training (1985 P01).** A counter works as a state machine that gates stations; each station has a short camera demonstration; repeating triggers give corrective hints when the player skips an obstacle; misconduct leads to LOOSE; each station transition saves.

## 4. Single-player mission craft

Evidence: the 24 official single missions plus four campaign training missions [V unless marked].

- **Size and logic.** 1,797 units, 706 triggers and 1,529 waypoints across the 24. 80% of triggers have a custom condition, 38% are zero-area logic triggers and 44% use timers. Script files are mostly camera work (21 of 24 missions). Seven single missions and all four training missions run timelines as chains of AND waypoints on game logics (64 and 118 waypoints).
- **Endings are a matrix.** Reachable END types per mission: one in 4, two in 8, three in 7, four in 2, five in 3. Endings vary by which targets were hit, how many enemy tanks died, the vehicle the player returns in (one of them comic) or an arrest for killing one's own commander. END numbers carry no meaning by themselves (in one mission END1 is the failure).
- **Survivable failure is an END code.** No single mission has a LOOSE trigger (23 campaign missions do). 18 of 24 have a reachable ending whose debrief title reads as a failure; 22 of 64 reachable endings are failures. The engine does pick a `Debriefing:Loser` section for LOOSE (`CWR:UI/Map/UIMapDialogs.cpp#L1064-L1087`), yet no briefing in the whole corpus defines one. Our reading: authors used END codes to get a distinct debrief per failure [I].
- **Cinematic endings.** In 11 of 24 an outro camera script sets a flag and a zero-area END trigger reading it calls `forceEnd`; the OutroWin and OutroLoose sections are empty in all 24. 10 have an Intro section, 13 fade in from black, 20 set loading text. Across all SP missions, 73% launch an outro script from a Mission-section trigger and OutroWin is used by 1%.
- **Boundaries.** 15 of 24 fence the play area. At least 8 use a soft two-tier boundary (a repeating warning by radio or the player's own voice, then an ending after a wider ring or a 30–60 s countdown); 9 use a hard "invisible fire" boundary (gunfire sounds, then the player dies 4–8 s later); 3 also end after an hour.
- **Escalation you can hear.** 17 missions have detection triggers (34); 12 use them to hold reaction groups until the player is detected. One mission releases six reaction groups with random delays of 15–100 s and raises the alarm 100–150 s after a patrol leader has been missing from his beat for 60–120 s. Five loop a siren that stops itself, two silence the birds after gunfire, five place a barking dog (25–30 m, any side) as a stealth tell.
- **Warnings.** Briefing notes name threats and a response (take cover from shelling; kill the static MGs first; a 15-minute window before helicopters). Radio warns of a minefield within 250 m, reports detection, counts down a convoy's departure at 2, 4, 6 and 7 minutes. Counter-examples also ship: a scripted death of an allied squad, and hard boundaries with 4–8 s of notice.
- **Anti-softlock.** Clear-area conditions accept "everyone left is fleeing" (5 missions) or "no enemy detected for 20–80 s" (5); a mission moves on if expected enemy armour has not come after 240 s. Objective units are never randomly absent, but one mission's triggers reference soldiers whose presence is random (and rely on case-insensitive identifiers).
- **Saves and safety.** `saveGame` in 11 missions (17 calls), after milestones, often from a second trigger 5–11 s after a flag. One scripted extraction makes the helicopter and player invulnerable (`allowDammage false`) for its duration.
- **Player agency.** Six missions use radio triggers (0-0-x) to start an attack, call support or call extraction; `setRadioMsg` shows the label only while the call is valid and hides it with "null".
- **The world keeps its own clock.** Six missions schedule events on long timers (a convoy leaving at 430 s after four radio warnings; an attack at 35 minutes or earlier if the player comes close; waves teleported to their start only while unobserved; helicopters at 900 s after a warning at 600 s).
- **Variety.** Seats: infantry 15, tank commander 2, AA crew 1, attack helicopter 3, transport helicopter 1, biplane 1, jeep race 1; two missions on the Soviet side; dawn is the house style (9 of 21 explicit hours); 7 use fog; 13 start the player alone. Each has one signature mechanic (stealing a vehicle, a race, a graded troop drop with a revealed medevac, laser designation, timed sniping with a player-called exfil, a sabotage deadline, beach defence under shelling, AA defence against heliborne waves).
- **Objectives.** `objStatus` in all 24 (123 calls); 11 fail or hide objectives and 5 reveal new ones mid-mission; objective 1 is often a movement or boarding step.
- **Briefing voice.** Notes are often first-person (a dated diary, a letter home, inner monologue) while the Plan gives orders plainly; every briefing links places to markers (2–16). 14 of 24 keep template placeholder text in unused slots and 4 reachable endings show a placeholder heading.
- **Guidance.** All 1,529 waypoints are saved with `showWP NEVER`, the editor's default for a new waypoint; the serialization default is EASY and CWR's map draws only EASY/ALWAYS waypoints (`CWR:AI/ArcadeTemplate.cpp#L1052`, `#L1120`). Authors guided instead with dotted route markers (117 Dot markers) and short imperative waypoint descriptions (45 in 16 missions); 80 invisible Empty markers serve as script anchors (`getMarkerPos` 118 times).
- **Sound and music.** 81 tiny ambient animal triggers in 11 missions plus sound-emitting objects; music marks boarding, a destroyed target or detected armour in 15 missions (`fadeMusic` 57 calls).
- **Discipline and plans.** Friendly fire and killing one's commander lead to arrest endings, rebukes with rating penalties or (in training) a punishment squad. Four missions adapt when the leader or a speaker dies: the player takes command, another leader takes the radio, a new ending opens.
- **How training teaches.** An in-world instructor; a phase variable that advances only on state; just-in-time control hints (24, 7 of them modal `hintC`) chained on game-logic waypoints with timeouts; twelve nag timers (typically 30–60 s); pass or retry feedback on every obstacle and target; hints that react to state (reload, find the medic); travel cut by fade, teleport, fade in and autosave; a living base; an 80 m leash that scolds, then fails the mission after 60 s. Tank training ends when a real alarm turns the exercise into combat; command training acknowledges a step solved another way and suggests drills while allies travel. The "training" single missions are low-risk real sorties with a control tip in the notes, a generous boundary and a gentle failure debrief.
- **Script style** ([`corpus-script-idioms.csv`](data/corpus-script-idioms.csv)). Pure SQS: 0 `.sqf` files, no `if/while/private` anywhere; flow is `? cond : stmt` (1,427 lines), `goto` (1,154) with labels, `@` waits (2,835) and `~` delays (2,920). No loop spins without a wait or an exit (356 polling, 171 iterate-and-exit). The pause after a spoken line has a median of 3 s (p75 6, p90 8). Fades: BLACK IN 507, BLACK OUT 365. AI orders: `setBehaviour` SAFE 441, CARELESS 276, COMBAT 124; `setCombatMode` BLUE 172, RED 92. About 11% of units carry an init line; the top idioms are behaviour, fleeing, damage, identity, start in cargo and weapons.

## 5. Multiplayer craft and the editor templates

### 5.1 The official set [V]

30 missions: 10 co-op against AI, 5 flag-fight deathmatch variants (one a team variant), 4 capture-the-flag, 2 sector control, 2 two-flag hold, 2 paintball, and one each of hold-flag, hold-area, king of the hill, attack/defend (plant and defuse) and a dogfight with landing. Slots run 3–17 (mean 8.7). For 8 of 30 the player range in the folder name disagrees with the real slot count, one "team" mission (shipped for two islands) is really a 3-player co-op, and 4 names break the `min-max_Letter_Name.world` convention. CWE's MP folder holds 28 of the 30, 26 byte-identical.

### 5.2 Settings [V]

- **Keys used.** `respawn` in 24 (BASE 19, GROUP 5; all 6 without it are co-op and fall back to the seagull default); `respawnDelay` in 19 (4–30 s, median 20); `param1` is always a time limit (19, default 1,800 s) and `param2` a score or hold limit (17), with 10000 as an "Unlimited" first entry; `disabledAI` 4, `aiKills` 3, `onLoadMission` 25. None uses `joinInProgress` or `CfgRemoteExec`.
- **What the 1.99 executable knows.** A string scan of `ColdWarAssault.exe` finds `disabledAI`, `aiKills`, `respawnDelay`, `titleParam1`, `valuesParam1`, `textsParam1`, `defValueParam1`, `showGPS`, `showMap`, `showCompass`, `debriefing`, `weaponPool`, `noAward`, `exitScore`, `lives`, `WIZVAR_`, `Debriefing:Loser`, `OBJ_WEST_` and the four respawn hook names. It does **not** contain `joinInProgress`, `CfgRemoteExec`, `titleParam3`, `playerCountMultipleOf`, `respawnVehicleDelay`, `killedEnd` or `init.sqf` [V strings; I that 1.99 has no JIP key, no third param and no `init.sqf`].

### 5.3 Respawn rules in the engine [V]

- Modes NONE/BIRD/INSTANT/BASE/GROUP/SIDE (or 0–5); BIRD (seagull) is the default and invalid values become NONE; SIDE reports "not implemented" and falls through to GROUP; GROUP falls back to seagull when nobody is left (`CWR:Network/NetworkServerMission.cpp#L281-L364`; `CWR:World/Entities/Infantry/SoldierOldMove.cpp#L1026-L1200`).
- Marker lookup: `respawn_<unit var>`, then `respawn_<leader var>`, then `respawn_west/east/guerrila/civilian`, then any marker whose name starts with `respawn`. Matching is a case-insensitive prefix with a random pick, so several markers give several spawn points; area markers give a uniform random point, icon markers the exact point, no marker means respawning where one died. A side without its own marker can match another side's marker through the bare prefix. There is no vehicle respawn.
- Hooks run only if a file of that name exists in the global `scripts\` path, then resolve mission, campaign, root (`SoldierOldMove.cpp#L874-L891`; `CWR:UI/OptionsUI.cpp#L630-L655`). Stock DTA (1.99 and 3.05) ships `onPlayerKilled`, `onPlayerRespawnAsSeagull` and `onPlayerRespawnOtherUnit` but **not** `onPlayerRespawn.sqs`, so a mission-local `onPlayerRespawn.sqs` for BASE/INSTANT would never run on stock data [I; probe]. No official mission overrides a hook; two re-equip respawned players through a repeating "not alive and local" trigger whose deactivation fires on respawn.

### 5.4 Locality and synchronisation [V unless marked]

- **Authority.** Official missions predate `isServer`: they place a server object (a game logic in 9 of 30, an AI civilian parked off-map in 3) and guard server work with `local <object>` (12 missions, 16 templates). One detects a dedicated server with `player == player`. Faguss's CWA scripting notes say CWA 1.99 added `isServer`, and the name is in the 1.99 executable [V-secondary; V string]. Doc 31 records that `isServer` is false in single player, so the compiler owns a guard that also works in SP.
- **Mirrors.** Triggers run on every machine. The server detects the event, sets a global and publicVariables it; every client's condition reads "(world test) or var == N" (13 of 30). `publicVariable` appears in 23 of 30 MP missions and in no SP `.sqm`. Only numbers, booleans and objects are ever broadcast; `publicVariableString` and `publicVariableArray` are absent from the 1.99 executable, and whether plain `publicVariable` carries strings or arrays in 1.99 is [U].
- **Start sequence (CWR).** The host sets `param1/param2` and broadcasts them; the briefing always shows; `init.sqs` runs at the briefing; no Intro or Outro section plays in MP, so one official mission's leftover intro never plays. Previewing an MP mission as SP leaves `param1/param2` undefined [I].
- **Slots.** Nine missions give playable slots AI behaviour (waypoints guarded by locality, HOLD synced to state triggers); the four modes AI cannot play set `disabledAI = 1`. Scripts that address slots by name guard against empty slots with a self-comparison test.

### 5.5 Mode anatomies [V]

| Mode | Core mechanism | Rules worth reusing |
| --- | --- | --- |
| Deathmatch | Everyone on one side, one-man groups, rating below −10,000 so all are renegades | `addScore` per flag delivery; the outro rewrites rating from score so the debrief ranks by score; the flag resets 30–60 s after its carrier dies |

### 5.6 Ending, briefing, bounds and balance [V]

- **One ending for all.** 19 of 30 end through one chain: end condition, summary title, a per-client camera outro, a flag, then END1 with `forceEnd`. Only six missions have more than one END type (three co-op, and three PvP that tell the sides or a draw apart); every briefing still carries six debrief sections. `estimatedTimeLeft` is set from `param1` in 17.
- **Per-side briefings.** The engine looks up `Main.<unit var>`, `Main.<leader var>`, `Main.<West|East|Guerrila|Civilian>`, then `Main` (and the same for Plan); objectives with prefixes `OBJ_WEST_`, `OBJ_EAST_`, `OBJ_GUER_`, `OBJ_CIVIL_` are side-filtered (`CWR:UI/Map/UIMapDisplayBriefing.cpp#L78-L136`, `#L427-L474`). 6 missions use per-side sections. One mission and all 5 of its templates (in 1.99 and 3.05) spell the resistance section `Main.guerilla`, which can never match.
- **Arena bounds.** 9 missions and 15 templates fence the arena with 48–85 sign objects and a ring of Dot markers; a server trigger adds 0.1–0.33 damage every 3 s to anyone outside, with no warning. Templates compute the ring with `cos`/`sin` from border anchors.
- **Balance.** Slots are symmetric except deliberate attack/defend asymmetry. Bases lie 232 m to about 2 km apart; a CTF team's own flag sits at 0.4–0.5 of the distance to the enemy flag, and the two sides' distances differ by 7–20%. Deathmatch spawn areas are 100–150 m, team spawn areas 10–50 m. Respawn delays: deathmatch 15–20 s, CTF 15–30 s, sector 5–10 s, hold 30 s, paintball 4 s in the round-based mission (20 s in the other).

### 5.7 Init-line and command patterns [V]

Custom ammo crates (cargo commands in 21 of 30 missions) and flag setup (22) dominate init lines. The top MP commands are `localize`, `publicVariable`, `setFlagTexture`, `titleCut`, the cargo commands, `exec`, `forceEnd`, the camera family, `hint`, `forEach`, `time`, `alive`, `local`, `list`, `setDammage`, `addScore` and `addRating`. `localize` is used 707 times in MP against 132 in SP. `addEventHandler` has 3 uses in the whole legacy corpus.

### 5.8 The template wizard [V unless marked]

- **Inventory.** 7 MP families across islands (31 templates); the 5 SP templates are the 1–6 co-op, with the same `mission.sqm` and scripts as the MP one (only overview pages and one loading text differ). The list shows only templates with a folder for the current island; CWR adds mod-packed templates (`CWR:Game/Mission/MissionTemplateCatalog.cpp#L39-L127`).
- **Flow.** Pick a template and read its overview; a map shows only `WIZVAR_*` markers, which can be dragged, box-selected and shift-rotated about their centre; on finish the engine copies the folder, sets `WIZVAR_<n>_X/_Y/_Z` globals, reloads `mission.sqm` so expression fields evaluate, deletes the anchors and saves (`CWR:UI/DisplayUIMultiplayerWizard.cpp#L259-L829`). CWR adds an Edit button; the 1.99 map dialog has only Cancel and Finish.
- **Parametric content.** 12,034 anchor-referencing fields in 72 template files (the 1.99 and 3.05 copies of 36 templates, 6,017 fields each), 1–15 anchors per template (one anchor moves a whole paintball arena; sector control uses 15); positions, facings (`atan2`) and trigger sizes are arithmetic over anchors. Island variants differ only in anchor defaults, and two families are byte-identical across islands, so their anchors keep the same coordinates everywhere.
- **Evaluation surface.** A non-literal numeric value in a config or SQM file is evaluated as a script expression at load (`CWR:IO/ParamFile/ParamFile.cpp#L815-L860`; `ParamFileEval.cpp#L107-L113`). The wizard relies on this, but any text `mission.sqm` or `description.ext` could use it; which commands can run there is untested [I]. Doc 24 does not list it yet.

### 5.9 Latent defects in shipped MP and template content [V]

An orphan trigger in a CTF template, placed after the Sensors list closes (never loaded); 6 VEHICLE-activated triggers with no attached object; a misspelt `description.ext` key the engine ignores; `Main.guerilla`; a mission with no END trigger; developer cheat triggers in 3 missions; an unreferenced script; `.bak` files in the 1.99 templates; and a global named `EndGame`, which CWR registers as a command that quits the game. The official missions stay safe only because an init trigger assigns it before any read; `endGame` is absent from the 1.99 executable and CE renamed its command, so the hazard is CWR-only [V strings; I runtime].

## 6. The community: CWE and the classics

### 6.1 Cold War Enhanced: a platform mod [V unless marked]

- **Shape.** CWE replaces the whole main config and UI resource with its own text files, adds core script PBOs (219 SQF functions; voice-system data), a 43-addon mod root, its own stringtable and a launcher that needs Fwatch and an external sound exe. While the game runs, the launcher renames the game's folders to hide external content; its own notes warn that they stay renamed if the launcher is killed.
- **Systems, not content.** 26 of 28 MP missions are byte-identical to official; the bundled 1985 campaign is an older revision than the 1.99 copy; only 3 official single missions were ported and 5 missions added. Porting a mission takes about ten mechanical edits: gear-pool classes remapped, a text re-save with the mod in `addOns`, optionally a module.
- **Dependency capture.** `CWE_Standard`'s `CfgPatches units[]` lists 168 vanilla classes. The engine adds the first patch whose `units[]` names a class, plus the class owner (`CWR:AI/ArcadeTemplate.cpp#L321-L352`), so every mission saved under CWE requires the mod even if it uses only vanilla classes. This is doc 27 §2.4's rule and its D3 case, seen in the wild.
- **Compatibility tools.** Stub addons keep old dependency names loadable; hidden classes use `scope` 1 or protected instead of removal, some with period-accuracy notes; comments forbid removing standard classes; a mod-identity array and a per-mod manifest are checked at start.
- **Modules before Eden.** 20 public game-logic classes in three editor categories cover six concepts (casualty collection point, POW collection point, take no prisoners, no extra POW points, extra casualty points, artillery). With no attribute UI in 1.99, each side and preset needs its own class; a config init handler runs a script that writes one positional preferences array. Config event handlers on unit classes (hit 79, init 35, killed 13, fired 11) give every placed unit the wounding, medic and voice systems, so CWE's own five missions need only 16 script files in total.
- **Changed idioms.** Wounded, surrendered and non-combatant units become captive, so "side NOT PRESENT" triggers stop working and the mod prescribes "side PRESENT" with a count of non-captive units; `saveGame` and `removeAllWeapons` are disabled and replaced, weather and fade commands bypass the mod's systems, and `addRating` needs a 0.25 s delay at start.
- **Its missions.** Large set pieces (115–418 units, 1–11 triggers) whose endings come from script loops over side lists: win at a force ratio of about 3:1, enemy retreat below a random strength of 4–14, staged objective reveals, a fake ambient barrage, an establishing shot.
- **Hacks the 1.99 language forces.** "Is defined" by comparing `format` output with the engine's undefined string; nested loops to dodge the 10,000-iteration cap; weapon classes used as per-unit state (91 `PLAYER_` variants, jammed variants); 1,204 accesses to one global array with 81 magic indices; 823 `call loadFile` function calls; 172 Fwatch calls; commands shadowed by globals.
- **Editor tooling.** A debug console (run code, pause, watch a variable) that works only in editor preview, a dynamic-trigger console, a hook that runs on every preview, preview hotkeys.
- **Risks.** A missing comma merges two entries in the dependency list; the folder-rename risk; a debug hook that ships live; an undocumented function library [I].

### 6.2 What players played in 2021 [V]

- **CTI dominated, on few servers.** CTI variants took 61.6% of MP player-hours (49.7% PvP or unspecified, 11.9% co-op against an AI side); other co-op at least 5.7%, team-vs-team 1.7%, deathmatch 0.7%, CTF 0.6%; 23.6% unclassified, 4.4% lobby. One server produced 18.3% of all player-hours and the top five 39%; the top mission was 12.3% of all hours at a mean of 1.5 players.
- **Tiny groups.** 1.96 humans per occupied server snapshot on average (CTI 1.7–1.9, co-op 2.8, TvT 2.7, CTF 3.1, DM 3.2); the peak on a named mission was 19. 230 of 1,846 mission names hold 80% of the hours; 1,127 names got under an hour.
- **Split versions.** 1.99 44.7%, the unofficial 2.01 patch 29.3%, 1.96 26.0%; clients join only servers of the same version. The top islands are all official (Everon, Nogova, the desert island, Malden, Kolgujev).
- **Authored is not played.** The OFP.info MP catalogue is 63% co-op; 2021 play went to CTI (a cross-era comparison). Community campaigns are mid-sized: median 11 missions (IQR 7–17, max 33) after removing duplicates and a winter conversion of the official campaign.

### 6.3 What made the classics loved [V unless marked]

- **Abandoned Armies** (OFPEC 10/10, the most-downloaded SP entry): one living-island mission lasting most of a day, everything placed at start with permanent losses, 42 radio savegames, 15 event-dependent cutscenes (players see about ten), changing three-way relations, a squad that grows and gains skill, a low-spec effects dialog.
- **The Black Gap** (9/10): the player leads one squad in a four-squad platoon; if the lieutenant dies the player takes platoon command through a dialog with map-click orders; the lieutenant picks one of several plans at random; endings depend on platoon strength; benchmark tiers gate units and effects; a court-martial ending exists for killing a friendly.
- **Role mechanics** made missions memorable: a forward observer plotting armour at dawn; airstrikes by coordinates with a targeting manual in the notes (Dead by Dawn, 2001, which also adapts view distance and unit count to `benchmark`); a homing-device hostage hunt whose location changes each play; door-gunner seats; a crash-and-walk-out.
- **Story campaigns** won on music (one cue per mission, never repeated), intros and outros per mission, character and a gentle ramp, mostly with basic editor-driven scripting; common faults were over-long shots, contained play areas, a two-hour first mission and leftover addon references.
- **Visible consequences** (court martial, desertion boundaries, a punishment outro) were praised; boundaries that merely contain the player were criticised.
- **Replay value** came from a few randomised key facts or from player-chosen alternatives (four insertions and four extractions through a dialog). Near-procedural dynamic campaigns were downloaded widely but reviewed as repetitive.
- **Good co-op** had a different intro per group, alternative approaches in the briefing, salvaged assets carried into later phases, an officer group plus 4-man fire teams, a hardcore loadout variant, and enemy artillery that fires on detection and then cools down on a random 4–8 minute timer.
- **A one-mission war with a hub** (take or abort sub-missions, rearm at base, map-click insertion, civilian deaths feeding the insurgency, status on demand) is a proven OFP form.
- **Retrofits and conversions** extended life: revive layers applied to 103 existing co-op missions (revive-tagged missions were 2.8% of 2021 hours); the official campaigns were converted to co-op packs; total-conversion mods carried their own mission ecosystems.
- **How they were built.** Dynamic campaigns use the campaign graph as a router (end codes pick the next mission type, `lost` retries, several classes share one template), which is field evidence for doc 18's shared-template claim. Their persistence is hand-unrolled per slot (one 13-slot block has a malformed line), and one popular campaign appears to be built on another's code [I]. They used commands official content never used: the dialog and list family, `onMapSingleClick`, `benchmark`, `knowsAbout`, `setFog`, `setRain`, `showMap`, `missionName` and SQS `if/then/else` (about 400 uses); a naive scan also reports false uses (English words in strings, `for`/`while` forms that do not occur).

## 7. Later Arma titles: what carried forward

### 7.1 Campaign structure [V unless marked]

- **Hub and sorties (Arma 3, East Wind).** Story missions separated by walkable camps; optional free-roam sorties at each camp never advance the story, and salvage brought back fills the camp armory automatically, with some gear obtainable only that way. BI's own fixes: persistence extended to all gear for the player and squad; a cargo box of items squadmates were holding, because players reported vanished gear as a bug; and a check against required gear instead of automatic re-dressing, to keep missions completable. Side content found only through camp chatter and lost when the story moved on was criticised.
- **Fail forward.** In Operation Arrowhead the outcome of one mission (target killed or escaped, hostages saved or killed) selects among three finales; in ArmA: Armed Assault failing an objective changes the story, and some major missions offer a choice of one of two sub-missions [V/V-search]. Harvest Red (Arma 2) is mostly linear with two free-roam missions whose tasks can be done in any order, a report-or-keep-quiet choice, NPCs who die if the player is late, and a faction choice that changes the path.
- **Framing and roles.** Laws of War frames flashbacks from several sides, including a civilian, through a present-day interview and adds no new punishment unless a scenario is about the issue; Tac-Ops lets some missions be replayed from another unit and treats objectives as completed, failed or ignored; Contact shows that non-shooting play (signal hunting) works, and its long walks, save-blocking danger zones and sparse checkpoints drew the most complaints.
- **Contingencies, not dependencies (Old Man).** More than 50 small missions sorted by location, side and quest; a failure in one system does not break the scenario; NPCs are expendable, items collectable, quests completable before they are assigned, and there is no traditional game over. Its modules were exposed in Eden but needed a community guide to be usable.
- **Systemic side content.** Arma 2's Secondary Operations Manager draws random side ops from 9 types near the player and grants supports (transport, supply drop, airstrike, artillery) the designer chooses; Reforger's Scenario Framework nests Area, Layer and Slot, with "spawn one random child" layers and counter, OR and switch logic entities.

### 7.2 Multiplayer and sandbox norms [V unless marked]

- **Lives economy (Apex Protocol).** Criticised at launch for missions that could not fail, no AI in empty slots and no saving; update 1.64 gave hosts Unlimited, a shared-ticket Limited mode (tasks add tickets) and Disabled respawn, plus revive options, and made "everyone down" a failure.
- **Clarity over progression.** Warlords dropped base building and player progression so a joining player knows what to do; open slots fill with AI; reinforcements are refused for a while after heavy losses. Reforger's HQ Commander issues seven task verbs (seize, attack, hold, resupply, build, recon, establish base) and creates resupply tasks automatically when a base runs low; players say support roles earn little [U].
- **Session generators.** Combat Patrol (vote a location, random objectives, alarm brings reinforcements, extract) and Reforger Combat Ops (three random objectives then exfil, playable solo). In the Workshop's top 60 Arma 3 scenarios (fetched 2026-09-27), 30 entries are generators but from only 3 design families, mostly per-terrain ports; Dynamic Recon Ops alone has about 305k subscribers.
- **Organised co-op.** Short (about 40 minutes for 20–50 players), one life, role slots, a commander who does not plan by committee; ShackTac's author plays company commander in the pre-mission phase; briefings stay short with background optional. The F3 kit packages 30–40 components (safe start, casualty cap, escape check, gear by role, ORBAT notes, group IDs, conditions and AI skill parameters, an ending controller, body removal, view distance, disable saving).
- **Balance.** BIKI defines TvT balance as an even chance for equally skilled sides, not symmetry, and accepts compensated asymmetry. The current goal must be crystal clear even when the end goal is hidden.
- **Visible escalation.** Antistasi's war level rises with weighted territory held (10 levels); KP Liberation's civilian reputation has ±25% thresholds with visible effects (informants and help above, IEDs and ambushes below).

## 8. 1.99 command evidence

### 8.1 What the observed-commands data proves [V]

[`cwa199-observed-commands.csv`](data/cwa199-observed-commands.csv) matches every SQS line and `.sqm` code field against the CWR registry (509 identifier-form names outside cheat blocks: of the 524 names doc 23 §3.2 counts as registered, the 15 symbolic operators `!`, `!=`, `%`, `&&`, `*`, `+`, `-`, `/`, `<`, `<=`, `==`, `>`, `>=`, `^`, `||` are not rows of the CSV; all 15 are registered in `BohemiaInteractive/CWR@ffc61838b7:engine/Evaluator/express.cpp`, and `GameStateExt.cpp` adds only further `==`/`!=` overloads [V]). Legacy official content uses 233 distinct commands (60,226 uses); `animationPhase` appears only in official configs; `captive` and `loadFile` only in CWE. Every identifier used in command position anywhere in the corpus is a registered CWR command, except three cheat-only `diag_*` commands in a developer dialog, so the CWR registry covers all non-debug command usage in this corpus (a corpus result, not proof about unseen 1.99-era content). Usage is concentrated: the top 20 commands make 57% of uses, the top 100 make 95%; 20 commands appear in one file each (weaker evidence). `setDamage` and `damage` appear beside `setDammage` and `getDammage` in Resistance-era content and share their handlers. Observation cannot prove absence: most official content predates the 1.85–1.96 additions.

### 8.2 New: the 1.99 executable string scan [V strings; I availability]

Method: for each of the 509 identifier-form registered names (of 524; the 15 symbolic operators, §8.1, are not searched), search `ColdWarAssault.exe` and `ColdWarAssault_Server.exe` (1.99, dated 2016-10-08) for the name as a NUL-terminated string, ignoring case. It is a byte search for names that are already public (the CWR registry); nothing is disassembled or decompiled, and only name presence is published. Bohemia's content rules forbid reverse engineering, and whether they cover even a name search is still doc 02's open question [U], so the scan stays a local check that the owner runs on their own install (rc90). **Recall is complete:** all 236 names observed in content are found in both files.
