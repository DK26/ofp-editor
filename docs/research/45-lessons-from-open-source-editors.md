# Lessons from open-source content-creation tools

Research doc 45 for Plotroom (`ofp-editor`). Research date: 2026-09-27. Audience: contributors and LLM coding agents. This file is meant to be read on its own.
Question answered (owner): "Are there lessons we can learn from other content-creating products? Maybe even open-source ones we can inspect their code." We read the source of 20 open-source repositories: Rust editors on our own stack, map and level editors, no-code and narrative tools, and game scenario editors with their content servers. The goal is to inform the next design step: the editor document model, commands and undo, entity identity, selection, the inspector, validation, threading and the UI shell.

## TL;DR

- **Make an unrecorded edit impossible.** Graphite wraps its document trees in a read-only guard whose field is private to a `store` module, so a write that skips the change record does not compile; UltimateDoomBuilder records undo inside its map-element setters [V]. Twine records undo only when a caller passes a description, so edits can silently escape undo [V]. → A `MissionStore` whose mutation API exists only inside an open undo group; every mutation patches the CST and records a typed op with its inverse (§2.1).
- **Undo is groups of per-field ops, not document clones.** Groups nest and fold into their parent (TrenchBroom), are held open across frames by a gesture state machine (Graphite), merge only inside one gesture and one origin (Tiled, 0 A.D. Atlas, Blockly), and record origin, label, selection and the documents they touched [V]. None of the studied editors has one undo group spanning several documents [I from their structures]; Plotroom needs it, because a Wilco turn can touch a campaign, two missions and a stringtable (§2.2).
- **Plan before apply; rejected commands never reach history.** OpenTTD test-runs every command and asserts that the real run matches, except for commands flagged `NoTest` [V, ideas only: GPL-2.0-only]; Fyrox pushes a command even when its execution only logged an error [V]. This is doc 21's propose → check → commit applied to every command, the user's included.
- **Identity lives in the sidecar, is merge-safe and is never reused.** OpenRA hands out the lowest free actor name again and uses the name as identity and as a Lua global; 0 A.D. rebuilds its id high-water mark from surviving ids at load [V]. → 128-bit `EntityId`s from an injected source, the script name kept separate (doc 04's `VarName`), delete that reserves id and list position (Fyrox), paste that remaps internal references (Tiled), and a confidence-scored re-match after the game's own editor re-saves the file (§2.3; this confirms doc 34 ed16's sidecar ULIDs and re-association).
- **"Unsaved" means the revision differs from the saved one.** Graphite, TrenchBroom and Tiled get this right; Fyrox and OpenRA stay dirty after undoing back to the save point [V]. Selection, camera and folds never dirty and never enter the document (Twine stores them in the document [V]).
- **Validation is pure, parallel and revision-stamped.** Rules read an immutable snapshot off the UI thread (UltimateDoomBuilder's checkers are parallel but read the live map, so fixing waits for analysis [V]). Quick fixes hang off diagnostic codes, work on a multi-selection and apply as one named group (TrenchBroom, UltimateDoomBuilder) [V]. Acknowledgements persist with a fingerprint; both of those editors keep them only in memory [V]. Codes are data files with failing and passing fixtures (Yarn Spinner ships failing ones only [V]).
- **Lossless beats "save may remove your comments".** Tiled, TrenchBroom and UltimateDoomBuilder drop comments, unknown elements or ill-typed values; GDevelop replaces unknown events with empty ones; Wesnoth's editor warns that saving removes comments and macros [V]. → Opaque nodes round-trip, load-time repairs are offered and never applied silently, and generated regions are tracked per field with hashes (§2.7).
- **Where metadata lives decides what leaks.** The CWR exporter packs the whole mission folder but skips sub-directories whose name starts with `.` (doc 04 §9 [V]). → The shared sidecar is a dot-directory (doc 22's `.ofpeditor/`, not doc 04's `ofp-editor.meta.toml`); per-user session state and the crash journal live in the app data directory. The 1.99 exporter's behaviour is [U] (open question 1).
- **One command catalog drives everything.** rerun's command enum feeds menus, the palette, shortcuts and agent callers, with stable ids, safety flags and errors that tell the caller how to recover; its MCP tool schemas are generated from the protocol's own doc comments [V]. → The `EditorCommand` registry (docs 17, 22) drives menus, palette, hotkeys, Drill steps, Wilco's tool manifest and the outbound MCP server.
- **Frame discipline for egui.** The document is immutable during a frame; every edit queues to one drain point in eframe's `App::logic` (rerun [V]; the method exists in eframe 0.36.2 [V docs.rs]); heavy work runs on workers over shared snapshots and returns results stamped with a revision (Graphite, rerun) [V].
- **No-code: typed sentences, ids not names, glass-box code generation.** GDevelop stores references by name and needs 24 project-wide `Rename*` entry points; Blockly stores variable ids [V]. Blockly can inject a per-block id before every emitted statement for tracing [V]. → Sentence templates with named, typed slots, rejected at pack load; `EmitMode::PreviewTrace` drives a fire log drawn on rule cards; export stays clean (§4).
- **Community content: derive, pin, sign, moderate reversibly.** BaNaNaS derives listing facts from the upload, pins dependencies by hash and hides superseded versions while keeping them resolvable; 0 A.D. verifies downloads against a pinned key but leaves the dependency list unsigned; Wesnoth's server has cheap moderation levers and its client refuses to overwrite a working copy [V]. Licences: 16 of 20 repositories can be ported with notices; OpenTTD, the two BaNaNaS services and scratch-vm are ideas only (§1). (Superseded in part by [D031](../decisions/D031-generated-content-permission-and-licence-scope.md) item 4, 2026-09-27: the two GPL-3.0-only repositories among the 16, Twine and OpenRA-Resources, are not ported by default.)

## 2. Architecture lessons for the next design step

### 2.1 Document model: one guarded store, one mutation path

**Best example: Graphite's store guard.** `NodeNetworkInterface` keeps its trees in `Guarded<T>`, a tuple struct whose field is private to the `store` module, with `Deref` and no `DerefMut`; mutators append an `EditorDelta`, and deserialisation records nothing, because a loaded document is the baseline, not an edit (`GR:…/document/NI/store/mod.rs#L10-L52`, `GR:…/document/NI.rs#L68-L106`) [V]. UltimateDoomBuilder gets the same guarantee differently: the setters of vertices, linedefs, sidedefs, sectors and things call a `Rec*` hook that serialises the before-state (`UDB:Source/Core/Map/Vertex.cs#L114,#L142,#L167`, `Linedef.cs#L139-L396`) [V]. Tiled uses one scripting API for open documents (an undo command) and for detached objects (a direct write) (`TI:src/tiled/editablemapobject.cpp#L342-L352`) [V]. rerun passes the narrowest of three tiered contexts and documents "never use the powerful one where the narrow one suffices" (`RR:crates/viewer_support/re_viewer_context/src/viewer_context.rs#L19-L50`) [V].
**Counter-examples.** Twine keeps `selected`, `highlighted` and `zoom` on its story and passage types and deny-lists some of them from triggering saves (`TW:src/store/stories/stories.types.ts#L8-L116`, `TW:src/store/persistence/persistable-changes.ts#L4-L31`) [V]. Wesnoth's side, schedule and scenario setters bypass undo entirely (`WN:src/editor/map/map_context.cpp#L294-L376`) [V].

```rust
// Proposal-only [I]. Module privacy, not a compile_fail doctest (AGENTS.md bans those), enforces the single mutation path.
pub struct MissionStore { cst: Guarded<ConfigDoc>, lens: Guarded<MissionLens>, sidecar: Guarded<Sidecar>, rev: Revision }
pub struct Guarded<T>(T);                        // field private to `store`; impl Deref, never DerefMut
pub trait DocMut {                               // implemented by LiveTx (journalled, undoable) and Scratch (a fork for proposals/import)
    fn set_field(&mut self, e: EntityId, key: FieldKey, v: FieldValue) -> Result<(), Error>;
    fn set_list(&mut self, owner: EntityId, list: ListKey, items: Vec<EntityId>) -> Result<(), Error>;
    fn create(&mut self, snap: EntitySnapshot, at: ListSlot) -> Result<EntityId, Error>;
    fn delete(&mut self, e: EntityId) -> Result<(EntitySnapshot, ListSlot), Error>;
}
pub struct AppCtx<'app> { /* catalogs, settings, command sender */ }
pub struct DocCtx<'doc> { /* read-only snapshot, selection, diagnostics */ }
pub struct EditCtx<'doc> { /* DocCtx + the open group + the command queue */ }
```

- `LiveTx` exists only while an undo group is open (§2.2). For a text mission each mutation patches the CST in place (doc 04 §12.3(2)); a binarized mission (doc 04 §12.2 `Origin::Rap`) goes through a rewrite path, because byte patching needs text [I].
- Each mutation records the **post-change value** and an inverse computed from the live state. Loading records nothing, so opening a mission gives an empty history (Graphite's `can_undo`) [V for Graphite].
- Workflows, importers and preview generators build on a `Scratch` fork; applying replays the same command list on the live store in one group, so the diff the user saw is exactly what lands (Tiled's pattern) [I].
- Wilco tools and plugins receive only doc 22's `MissionQuery` scopes derived from `DocCtx`. Lifetimes are named after what they borrow (`'doc`, `'catalog`) per AGENTS.md.
- The document holds no view state (§2.4). Tests: every public mutator emits at least one op; for a text mission, `render` after an edit differs from the original only inside the patched spans.

### 2.2 Commands, transactions and undo

**Ops.** Graphite's `EditorDelta` carries post-change values, snapshots whole metadata only for a just-created node, and replaces a whole array only where an insert shifts later entries (`GR:…/document/NI/editor_delta.rs#L14-L81`) [V]. It added `SetNodeImplementation` because remove-plus-re-add would clear the node's name, lock and pin (`GR:document/graph-storage/src/crdt.rs#L96-L133`); its diff-based fallback still emits remove-plus-add (`GR:document/graph-storage/src/delta.rs#L50-L66`) [V]. → `Op` = `Create | SetField | SetList | Delete | SetSidecar`. `SetList` covers `ItemN` renumbering (doc 04 §12.3(4)). "Change unit class" is `SetField(vehicle)`, never delete-plus-create, on every path, including text-mode Apply (doc 37) and "revert as a new change". `Delete` records the snapshot, the `ItemN` index and the parent list, and undo re-inserts at that index, so `ItemK` numbering, group order and bytes come back identical (Fyrox's delete keeps the id but may lose sibling order [I]: `FY:editor/src/scene/commands/graph.rs#L385-L436`).

**Groups, nesting and gestures.** TrenchBroom keeps a stack of open transactions; commands inside go into the innermost, a commit folds it into the parent or onto the undo stack, a rollback undoes in reverse, and an unfinished RAII transaction is logged as a bug (`TB:lib/TbMdlLib/src/CommandProcessor.cpp#L47-L141,#L211-L247,#L368-L425`, `TB:lib/TbMdlLib/src/Transaction.cpp#L66-L98`) [V]. Graphite's `TransactionStatus {Started, Modified, Finished}` cancels a transaction that changed nothing and rolls back an aborted one (`GR:…/document/NI/types.rs#L875-L881`, `GR:…/document/document_message_handler.rs#L1352-L1412`) [V]. A lexically scoped Rust guard cannot hold a drag open across egui frames, and neither can it hold a Wilco turn that streams over many frames [I].

```rust
// Proposal-only [I]. One open-group slot per project, owned by the command layer; an enum state machine per AGENTS.md.
pub enum OpenGroup {
    Idle,
    Started  { token: GroupToken, kind: GroupKind, scope: TxScope },                      // nothing changed yet
    Modified { token: GroupToken, kind: GroupKind, scope: TxScope, ops: Vec<Recorded>, merge: Option<MergeKey> },
}
pub enum GroupKind { Gesture(GestureId), AgentTurn(TurnId), WorkflowStep { run: RunId, step: StepId },
                     PluginBatch(PluginId), QuickFix(FixId), Migration(MigrationId), Import }
pub enum TxScope { Atomic, Live }                // TrenchBroom's Oneshot / LongRunning
pub struct Recorded { op: Op, inverse: Op }
pub struct UndoGroup { id: GroupId, origin: Origin /* doc 21/22 */, label: LabelKey, ops: Vec<Recorded>,
    touched: BTreeSet<DocumentId>, selection_before: Selection, selection_after: Selection }
pub struct MergeKey { gesture: GestureId, targets: TargetSet, field: FieldKey }
```

1. **Open, join, end.** Pointer-down, focus, a turn start or a workflow step opens the slot. A begin while open joins it, so a sub-step that asks for its own group folds in (Graphite's paste-name bug, `GR:…/document/storage_tests/round_trip_tests.rs#L493-L519`) [V]. End on a `Started` group leaves no history entry. Abort (Esc, right-click, a failed or cancelled turn) applies the inverses in reverse order; Twine replays them forward (`TW:src/store/undoable-stories/reverse-thunk.ts#L7-L28`) [V]. A scoped guard is only sugar for synchronous work such as one quick fix; dropping it uncommitted rolls back.
2. **Who sets the boundary.** Confirm mode: one group per Wilco turn; Auto: one per workflow step (doc 21 §7.3); a plugin batch: one `Origin::Plugin` group (doc 22). The boundary follows the autonomy mode, not a fixed rule.
3. **Observability.** TrenchBroom tags each state as observable or not and fires "document changed" only for observable modifications (`TB:lib/TbMdlLib/include/mdl/TransactionScope.h#L25-L31`, `TB:lib/TbAppLib/src/MapDocument.cpp#L426-L442`) [V]. → `Live` groups (drag, rotate, slider scrub) let the map renderer and inspector see intermediate revisions; validators, Wilco, the campaign graph and the journal see committed revisions only. Change events fire after history is updated (TrenchBroom needs a deferred-timer workaround because it fires first, `TB:lib/TbUiLib/src/MapWindow.cpp#L845-L865`) [V].
4. **Commit hooks.** TrenchBroom propagates linked groups once, at the observable commit, and cancels the whole transaction if propagation fails (`TB:lib/TbMdlLib/src/Map.cpp#L479-L495,#L1512-L1534`) [V]. → At the outermost commit, in order: linked-instance and template sync, no-code lowering including doc 31 §4.5's compiler-owned singletons, reference integrity. All generated edits join the same group; a failure refuses the group with a typed `Rejection`.
5. **Merging.** Tiled merges consecutive commands with the same kind id and marks a merged change obsolete when it returns to the original value (`TI:src/tiled/undocommands.h#L27-L75`, `TI:src/tiled/changevalue.h#L78-L94`); Atlas closes the merge window at gesture end (`0AD:source/tools/atlas/AtlasUI/General/AtlasWindowCommandProc.cpp#L54-L75`, `…/ScenarioEditor/Tools/Common/Tools.cpp#L179-L194`); Blockly merges only adjacent events of one group; TrenchBroom uses a 1,000 ms window and its test has to sleep (`TB:lib/TbMdlLib/test/src/tst_CommandProcessor.cpp#L1019`) [V]. → Merge only adjacent commands with the same `MergeKey`, never across origins; drop obsolete merges; use a time window only for typing, through an injected `Clock`.
6. **Plan, then apply.** OpenTTD runs each command in test mode, then for real, and asserts equal cost and failure unless the command is flagged `NoTest` (`TTD:src/command.cpp#L271-L366`) [V; ideas only]. 8. **One project-level history.** Fyrox keeps one command stack per scene (`FY:editor/src/scene/controller.rs#L43-L172`); Wesnoth and OpenRA keep one per map [V]. → One history per project whose groups record every document they touched. Undoing a group that touches a closed mission loads its model headlessly. Doc 34 ed22's per-origin lanes ("Undo last Wilco change") are filtered views over origin-tagged groups; reverting a group that is not on top requires its ops to commute with later groups, and if a later human group touched the same fields the user is asked (no-clobber) [I].

### 2.3 Stable identity

**What we saw.** Graphite mints 64-bit node ids as a truncated blake3 hash of (peer, counter), with one counter shared by all peers and persisted with the document, and pins a regression where ids came from traversal order (`GR:document/graph-storage/src/document.rs#L35-L52`, `GR:…/document/storage_tests/round_trip_tests.rs#L102-L137`) [V]. rerun's `Tuid` is 128 bits: time plus a per-thread increment that starts at a random value (`RR:crates/utils/re_tuid/src/lib.rs#L1-L33,#L55-L68,#L180-L200`) [V]. Tiled persists `nextobjectid`; paste gives copies new ids and rewires only references that point inside the pasted set (`TI:src/tiled/objectreferenceshelper.cpp#L32-L97`) [V]. Fyrox's delete keeps the pool slot reserved so undo returns the same handle, and frees it only when the command leaves history (`FY:fyrox-core/src/pool/mod.rs#L1030-L1099`, `FY:editor/src/command/mod.rs#L232-L281`) [V]. LDtk keeps UUIDs and a reverse-reference index (`LD:src/electron.renderer/data/Project.hx#L481-L536`) [V].
**Counter-examples.** OpenRA reuses the lowest free `ActorN`, uses the name as hash key and Lua global, and renames by remove-plus-re-add; no lint checks that script actor names exist (`ORA:OpenRA.Mods.Common/Traits/World/EditorActorLayer.cs#L447-L454`, `ORA:…/Widgets/Logic/Editor/ActorEditLogic.cs#L576-L587`, `ORA:OpenRA.Mods.Common/Scripting/Global/MapGlobal.cs#L34-L36`) [V]. 0 A.D. can reuse a deleted highest id in a later session (§1.2) [V]. LDtk silently drops lost references on load (`LD:src/electron.renderer/data/inst/FieldInstance.hx#L786-L856`) [V]. GDevelop events have no general persistent id: only events made by an AI or external tool carry an optional, saved `aiGeneratedEventId` (`GD:Core/GDCore/Events/Event.h#L313-L344`, `GD:Core/GDCore/Events/Serialization.cpp#L224-L225,#L243-L244`) [V]; other events are addressed by pointer or tree position [I].

- The file's own ids cannot be identity: the engine's editor renumbers unit and sync ids on every load and save (`Compact`, doc 04 §3.9) [V per doc 04]. Doc 34 ed16 already proposes ULIDs, which are this shape, in the sidecar; this section adds injection, prefixes and the tests.

- Transient entities (Wilco ghosts, drag previews, placement previews) are a separate `PreviewEntity` type the serializer does not accept; 0 A.D. filters them at save time with a flag (`0AD:source/graphics/MapWriter.cpp#L319-L334`) [V].
- Tests: load → save → load keeps ids; a simulated engine re-save (`Compact`) re-matches; merging two branches does not collide; deleting a unit with a synced trigger from the middle of a group, then undoing, restores the sync, the selection and the bytes.

### 2.7 Persistence and round-trip fidelity

**Losses we saw.** Tiled skips unknown XML elements, TrenchBroom's parser skips comments, UltimateDoomBuilder drops a declared field whose value has the wrong type, GDevelop replaces an event of unknown type with an empty one, and Wesnoth's editor preprocesses the scenario and warns that saving may remove comments and macros (`TI:src/libtiled/mapreader.cpp#L233-L239`, `TB:lib/TbMdlLib/src/StandardMapParser.cpp#L276-L290`, `UDB:Source/Core/IO/UniversalStreamReader.cs#L500-L570`, `GD:Core/GDCore/Events/Serialization.cpp#L206-L229`, `WN:src/editor/map/map_context.cpp#L443-L452`) [V]. Twine repairs stories on load but deliberately does not save a repair until the next real edit (`TW:src/store/persistence/local-storage/stories/save-middleware.ts#L24-L31`) [V].
**Good mechanisms.** Graphite re-converts and compares the document after each commit when a preference is on, panicking in tests (`GR:…/document/document_history.rs#L264-L345`); its manifest is always JSON with a checked `format_version`, session state is a separate file, and the working copy lives in app data (`GR:document/format/src/manifest.rs#L1-L50`, `…/session_state.rs#L1-L42`, `…/layout.rs#L9-L21`); hot ops are journalled, promoted at interaction boundaries, and replayed idempotently after a crash (`GR:document/graph-storage/src/session.rs#L133-L167,#L261-L321`) [V]. LDtk migrates its JSON in code gated by version, sets compatibility flags so exports do not change, and avoids churn in diffs (`LD:src/electron.renderer/data/Project.hx#L262-L374`) [V]; Graphite's migration file is 3,684 lines of string replacements (`GR:editor/src/messages/portfolio/document_migration.rs`) [V]. OpenRA warns before overwriting a map that changed on disk since it was loaded (`ORA:OpenRA.Mods.Common/Widgets/Logic/Editor/SaveMapLogic.cs#L261-L287`) [V]. OpenTTD keeps an append-only gamelog of fundamental changes inside the save (`TTD:src/gamelog.h#L17-L99`) [V, ideas only].

| --- | --- | --- | --- |

- Every Plotroom format carries `format_version` from the first release; each bump adds a typed `migrate_vN_to_vN1` with golden synthetic fixtures; migrations dry-run by default, apply as one undo group and are recorded in the project log. `mission.sqm` is never migrated; only "Normalize as engine" rewrites it (doc 04 §12.3(3)).
- Unknown sidecar records and rules or modules whose definition is missing load as `Opaque { def_key, version, raw }`, keep their bytes, show "needs pack X vN", block export, and write back unchanged. Load-time repairs become `RepairNote`s, applied as an ordinary command only when accepted (doc 04 identity invariant; doc 19 §7.6).
- `verify_round_trip_each_commit` is always on in tests and CI and optional in beta builds: after each commit, render, re-parse, and assert byte identity outside patched spans (text origin) plus lens equality. It extends doc 04 §12.3(10), which already requires a re-parse before replacing the file.
- The crash journal appends committed op batches with a hash of the base file bytes; on reopen after a crash it verifies the base hash and offers replay, or a diff if the file changed on disk meanwhile. Before every save, compare the on-disk hash with the one recorded at open and offer reload, overwrite, or save-a-copy-and-diff.
- Generated regions (scripts, `description.ext` classes, briefing sections) and generated **fields** carry a region id and a content hash; regeneration replaces only unchanged ones and adopts the rest as human work (doc 31 §8.3). Wesnoth shows the risk: its editor silently owns scalar scenario keys as well as whole blocks (`WN:src/editor/map/map_context.cpp#L640-L691`) [V].
- Shared files iterate `BTreeMap`s and keep volatile values (timestamps, auto-layout coordinates) out, so diffs stay small. The campaign sidecar gets a canonical sorted text form with inline layout, like Twee (`TW:src/util/twee.ts#L27-L322`), but, unlike Twee, `NodeId`, `EdgeId` and `VarId` persist across export and import.
- An append-only project log in the sidecar records the Plotroom version per save, target-profile and mod-set changes, pack substitutions, migrations, imports and Wilco runs; "copy diagnostics" exports it redacted by default.

### 2.9 Threading and frame discipline

**What we saw.** rerun loads its blueprint at frame start, keeps it immutable during the frame, queues changes as commands and applies them at the end of the frame (`RR:crates/viewer_support/re_viewport_blueprint/src/viewport_command.rs#L1-L55`); its command sender uses unbounded channels with `#[track_caller]` locations (`RR:crates/viewer_support/re_viewer_context/src/command_sender.rs#L286-L366`); `App::logic` drains commands and data even when the window is hidden, and takes its store hub out of `self` with `.expect()` (`RR:crates/top/re_viewer/src/app/logic.rs#L21-L94`) [V]. Graphite's dispatcher processes child messages before siblings, defers and de-duplicates side-effect-free refresh messages, buffers UI updates to the next frame and drains async results at one point, with an indented message trace (`GR:editor/src/dispatcher.rs#L59-L184,#L398-L428`) [V]. 0 A.D. Atlas keeps its UI and game on separate threads that exchange typed messages; queries block on a semaphore (`0AD:source/tools/atlas/GameInterface/MessagesSetup.h#L27-L105`) [V]. GDevelop validates every parameter of every rendered instruction during React render, which works because React re-renders selectively and the list is virtualised (`GD:newIDE/app/src/EventsSheet/EventsTree/Instruction.js#L296-L315`) [V]; in egui, the same call would run every frame [I].

1. **Logic step** (eframe `App::logic`): drain the command queue → plan → commit → publish an `Arc<Snapshot>` at the new revision; drain background results (validation shards, lowering, catalog scans, Wilco streams, Preview status) and drop those computed for a stale revision (doc 21's `reads: RevisionSet`); coalesce `Revalidate`, `RebuildDrawList` and `RelayoutCampaignGraph` to once per step.
2. **UI step**: reads `DocCtx` and caches only; never validates, never mutates; every edit is a queued command, traced with `Location::caller()` in debug builds.
3. **Workers**: validation pool, lowering, catalog scans; the model provider lives in its own crate (doc 21 §1.3). Workers receive snapshots and return revision-stamped results. The model's thread never touches the document.
4. Snapshots need structural sharing (`Arc`-shared CST subtrees or a persistent-collection crate) [I]; the cost is [U] and belongs in the doc 06 §7 proof of concept. A dedicated document thread (Atlas-style) is the fallback if commits stall frames [I].
5. Split handlers by area under the ~600-line ceiling (Graphite's single document handler is 4,392 lines [V]); split state into disjoint structs instead of rerun's take-and-`expect` trick, which AGENTS.md forbids.
6. Long lists allocate every row but paint and query only visible rows, and aligned columns use layout statistics from the previous frame (`RR:crates/viewer_support/re_ui/src/list_item/list_item.rs#L585-L597`, `…/list_item/scope.rs#L6-L92`) [V]. Keep doc 06 §4.4's offscreen texture; rerun's paint-callback route (`RR:crates/viewer_support/re_viewer_context/src/gpu_bridge/re_renderer_callback.rs#L1-L91`) stays the documented alternative.

## 4. No-code and narrative lessons

### 4.1 Event sheets, graphs and spaghetti

GDevelop's sheets are lists with an implicit, short-circuit AND; `Or`, `And` and `Not` are advanced containers whose help text steers users to flat lists and sub-events (`GD:Core/GDCore/Extensions/Builtin/CommonInstructionsExtension.cpp#L63-L103`, `GD:Core/GDCore/Events/CodeGeneration/EventsCodeGenerator.cpp#L466-L506`) [V]. Twine derives its graph by regex from passage prose, so a rename rewrites other passages' text (`TW:src/util/parse-links.ts#L1-L79`, `TW:src/store/stories/action-creators/update-passage.ts#L62-L113`) [V]. ink structures dialogue as nested choices and gathers, auto-joining loose ends (`INK:compiler/ParsedHierarchy/Weave.cs#L174-L270`) [V]. → Plotroom's split [I]: mission logic is sheet rows (doc 31 WHEN/IF/THEN; the IF clause is an implicit ALL; ANY and NOT are labelled containers behind Advanced; empty containers and one-child ANY are linted with a flatten fix; doc 31 §5.1 currently shows explicit, equal "ALL of / ANY of" containers, so moving ANY behind Advanced is a proposed change for the design round, not a restatement); campaign flow is a typed graph whose edges are rows in each node's transition table pointing at `NodeId`s (doc 19 §5.5, §6.2); conversations are trees of beats. Graphs are used only for flow; "reads or sets variable" is a derived, toggleable reference layer.

### 4.2 Vocabulary items are typed sentences

GDevelop instructions carry sentences with positional `_PARAMn_` slots rendered as clickable spans, and the formatter shows defaults for empty optional slots (`GD:Core/GDCore/IDE/Events/InstructionSentenceFormatter.cpp#L26-L103`); coverage is only a soft warning in the extension editor (`GD:newIDE/app/src/EventsFunctionsExtensionEditor/EventsFunctionConfigurationEditor/SentenceErrorMessage.js#L31-L63`) [V]. Blockly's `interpolate` throws when a message token is out of range, duplicated, or an argument is never referenced (`BL:blockly/core/block.ts#L1950-L2032`) [V]. → Every event, condition atom, action and module carries a localisable sentence with **named** slots; the T0 pack loader rejects a missing, unknown or repeated slot for every pack. The rendered sentence is doc 31 §4.1's one-sentence summary, the why-card text and what Wilco reads back to check intent. Cleared slots return to their computed default chip, as Blockly's shadow blocks respawn (`BL:blockly/core/connection.ts#L471-L490`) [V]; only user overrides are stored.

### 4.3 References by id, rules by mode

GDevelop references objects and variables by name inside expression strings; `WholeProjectRefactorer.h` has 878 lines and 24 public static `Rename*` entry points, and its migrations rewrite positional parameters (`GD:Core/GDCore/IDE/WholeProjectRefactorer.h`, `GD:Core/GDCore/Events/Serialization.cpp#L182-L199`) [V]. Blockly's variable field stores the variable id (`BL:blockly/core/field_variable.ts#L150,#L213`) [V]. → Parameters are `BTreeMap<ParamKey, ParamValue>` with `EntityRef(EntityId)` values and stable enum keys; names are written only when lowering. GDevelop's "Trigger once" is a condition that must be last and is silently moved there (`GD:newIDE/app/src/EventsSheet/OnceInstructionSanitizer.js#L4-L31`); Scratch builds edge detection into the hat, per target and block, firing on false→true and on a first true (`SV:src/engine/runtime.js#L1986-L2059`) [V]. → Keep doc 31's `RuleMode` (Once, Repeat, WhileTrue, AtStart) on the rule, define whether a condition true at mission start counts as an edge, and make an invalid mode a type error, never a silent repair. Escape hatches (expression slots, detached scripts) store the entity references they use, extracted by the doc 23 language service or confirmed by the user, as GDevelop's JavaScript event exposes its object parameter to refactorers (`GD:GDJS/GDJS/Events/Builtin/JsCodeEvent.cpp#L21-L82`) [V].

### 4.4 Behaviours, extensions and "extract to module"

GDevelop vendors installed extension definitions into the project with their origin, computes the extensions actually used, and ships typed breaking-change notes that drive an update dialog (`GD:newIDE/app/src/AssetStore/ExtensionStore/InstallExtension.js#L171-L328,#L515-L553`, `GD:Core/GDCore/IDE/Events/UsedExtensionsFinder.h#L28-L90`) [V]; the hand-written changelog accessors are wrong (`GD:Core/GDCore/Project/EventsFunctionsExtensionChangelog.h#L31-L36`) [V]. Its "extract to function" infers typed object and behaviour parameters from what the selection uses, but not variables (`GD:newIDE/app/src/EventsSheet/EventsFunctionExtractor/index.js#L18-L164`) [V]. → A mission that uses a pack module pins the `ModuleDef` (content-hashed, with origin and `min_plotroom_version`) in the sidecar, so it opens and lowers without the pack; the pack manifest must declare a licence that allows embedding, or vendoring is refused (doc 34 mo13). Upgrades show notes and the per-instance lowering diff and apply as one group. "Extract to module" (doc 31 §5.5) infers typed params from EntityRefs, flags, radio slots and markers, and warns above 5 basic parameters.

### 4.5 Story formats are compilers

A Twine story format is the runtime: the editor publishes a neutral data island and substitutes it into the format's template; editor extensions are keyed by a semver range of the Twine version (`TW:src/util/publish.ts#L49-L162`, `TW:src/util/story-format/editor-extensions.ts#L4-L38`) [V]. → The per-profile lowerings (Cwa199, Cwr, Ce; doc 31) are core compilers; plugin-supplied lowerings are sandboxed T1 functions returning typed proposals, never AST hooks (ink) or evaluated script (Twine). Profile badges are computed from what was emitted.

### 4.6 Narrative structures

- **Beats with gathers and TODOs.** ink auto-joins a choice without a divert to the next gather, requires explicit diverts inside sealed conditionals, and treats a trailing `TODO:` as an author note that skips the termination check (`INK:compiler/ParsedHierarchy/FlowBase.cs#L253-L262`, `INK:compiler/InkParser/InkParser_AuthorWarning.cs#L7-L24`) [V]. → Doc 31's Conversation module is a tree of `Line`, `Choice`, `Gather`, `Branch { guard }`; a `Todo { note }` element valid anywhere downgrades "unterminated" findings to author notes and keeps drafts runnable in Preview, while export refuses.
- **State-dependent variants.** Yarn Spinner's node groups score each `when:` header by its boolean operators and choose the most specific unseen variant, writer order breaking ties (`YS:YarnSpinner.Compiler/NodeGroupCompiler.cs#L78-L199`, `YS:YarnSpinner/Saliency/BestLeastRecentlyViewedSaliencyStrategy.cs#L15-L95`) [V]. → Briefing, debrief and dialogue `VariantSet`s ordered by specificity and lowered to a first-match chain of guards; the editor shows which variant each what-if state picks and lints unreachable ones; view counts are declared variables with a saveVar cost (docs 19, 26, 43).
- **Line ids.** Yarn Spinner adds `#line` tags only when the parse has no errors, with a minimal token rewrite (`YS:YarnSpinner.Compiler/Utility.cs#L126-L183`) [V]. → A `LineId` at creation keys the stringtable row, the sound class, voice assets and translation; imports assign ids in the sidecar without touching text.
- **One source of node facts.** Yarn Spinner's compiler emits `NodeMetadata` (jumps, variables, characters, tags, preview text) for graph and language-server use, next to a second, separate connection walker (`YS:YarnSpinner.Compiler/NodeMetadata.cs#L8-L183`, `YS:YarnSpinner.Compiler/Utility.cs#L698-L722`) [V]. → One `NodeSummary` per element feeds graph cards, the Variables panel, the screenplay outline and Wilco's scope header.
- **Infer, then declare.** Yarn Spinner infers undeclared variables from usage and can write the declarations back (`YS:YarnSpinner.Compiler/Declaration.cs#L365-L372`, `YS:YarnSpinner.Compiler/Utility.cs#L26-L124`) [V]. → For imported campaigns (doc 19 §7.6), infer types of `Opaque` variables from their uses and offer one `DeclareVariables` command.
- **Stubs.** Twine creates placed stub passages for new link targets and deletes them when unlinked only if they still look untouched (`TW:src/store/stories/action-creators/create-newly-linked-passages.ts#L12-L96`, `…/delete-orphaned-passages.ts#L11-L69`) [V]. → Typing a new target in a transition row creates a stub node in the same group; it is removed with its last edge only if its provenance is still "auto-stub" and it has no human edits, moves included.

### 4.7 Glass-box code generation

## 6. What to avoid

- Undo that callers must remember to record (Twine), side-door setters outside undo (Wesnoth), or plugins handed `&mut Editor` with "use commands" as advice (Fyrox) [V].
- Pushing commands that failed, context downcasts that panic, and `unsafe` in the command path (Fyrox) [V].
- Whole-document clones per transaction as the long-term undo (Graphite's default path, which it is replacing) [V].
- Remove-plus-re-add for a type or class change; it clobbers attributes (Graphite's diff fallback) [V].
- Time-window merging that needs sleeps in tests (TrenchBroom), trimming that splits groups (Blockly), silent trimming (Wesnoth) [V].
- History wiped by schema, catalog or non-undoable changes (LDtk, TrenchBroom) [V].
- A sticky dirty flag (Fyrox, OpenRA) or a counter forced so it can never reach zero again (Wesnoth) [V].
- Reusing ids, names as identity, rename as delete-plus-add (OpenRA); ids rebuilt from survivors (0 A.D.); persistent ids only for AI-made elements (GDevelop) [V].
- View state inside the document (Twine; GDevelop's folds and expanded flags) [V].
- Validators that read the live document and block fixing (UltimateDoomBuilder) or keep hidden mutable caches (TrenchBroom's mod validator) [V].
- Ignore lists kept only in memory (TrenchBroom, UltimateDoomBuilder); suppressions that disable "most checks" (`wmllint`) [V].
- Dropping unknown content, comments or ill-typed values (Tiled, TrenchBroom, UltimateDoomBuilder, GDevelop); preprocessing then rewriting (Wesnoth); silent tidying of lost references (LDtk) [V].
- Auto-repairing on load and saving the repair (TrenchBroom); positional parameters rewritten by migrations (GDevelop); migrations by string replacement (Graphite) [V].
- Compiling bad input into comments (GDevelop) or ordering output by canvas position (Blockly) [V].
- Clear-and-rebuild regeneration that wipes hand-tuned rules (LDtk) and unseeded randomness in generators (Tiled) [V].
- Extensions with File and Process APIs (Tiled), native DLLs that rewrite the AST (ink), `new Function()` on downloaded strings (Twine), trust keyed by an id inside the downloaded file (LDtk), an editor exit on a plugin version mismatch (UltimateDoomBuilder) [V].
- Agent integrations that run general coding agents or tell the agent to use external command-line tools (rerun's `re_agent` and MCP instructions, `RR:crates/top/re_viewer_mcp/src/instructions.md#L6`) [V].
- Badges that fail open or rely on heuristics that drift from the engine's own rule (OpenRA, the Resource Center) [V].
- Unsigned dependency metadata next to signed payloads (0 A.D.); bare dependency ids (Wesnoth) [V].
- One 4,392-line handler (Graphite) and `take().expect()` borrow tricks (rerun) [V].

## Open questions

1. **Sidecar spelling and export.** Doc 04 §12.3(11) names a file (`ofp-editor.meta.toml`), which the CWR exporter would pack; doc 22 names a dot-directory (`.ofpeditor/`), which it skips (doc 04 §9 [V]). Does the 1.99 exporter also skip dot-directories [U, needs a probe]? Candidate design-gap request against docs 04 and 22.
2. **Three `Origin` types.** Doc 04 uses `Origin::Text | Rap` for the config source, docs 21, 22 and 38 use `Origin` for authorship, and doc 26 uses `Origin` inside `Tracked<T>` for provenance. Proposal: `ConfigOrigin`, `Origin` and `Provenance` (with a `Template` variant). Candidate design-gap request.
3. **Workflow journal location.** DG017 proposes the workflow journal in the sidecar; if the sidecar is not a dot-directory, the game's own exporter would pack briefs and model replies into PBOs [I]. The crash op journal proposed here lives in app data. Should the two be one store?
4. **Id minting.** Random, time-ordered 128-bit ids (doc 34 ed16's ULIDs), or Graphite's (installation, counter) hash? Doc 19's `NodeId(u32)` would collide on merge the same way as a unit counter.
5. **Snapshot cost.** Structural sharing for `Arc<Snapshot>` per revision: which crate, and what does a large mission cost per commit [U, benchmark in the doc 06 §7 proof of concept]?
6. **Live edits.** Apply `Live` group ops to the store with observability flags (proposed), or keep uncommitted edits in an overlay the renderer reads? Decide together with crash and journal semantics.
7. **Out-of-order revert.** The conflict view when a Wilco group does not commute with later human groups (doc 34 ed22, doc 38).
8. **Campaign layout.** Doc 19 stores `layout: CanvasPos` on every node; LDtk-style auto layout suggests `Option<CanvasPos>` with `None` meaning "auto". Candidate design-gap request.
9. **Re-match thresholds** after an external save: which fingerprint fields, what confidence counts as automatic [U].
10. **Twine ports.** Ported Twine files stay GPL-3.0-only; does DG018's header format need a "licence of this file differs from the project" marker? (answered 2026-09-27 → [D031](../decisions/D031-generated-content-permission-and-licence-scope.md) item 4: GPL-3.0-only code is not ported by default; a case-by-case port needs the owner's sign-off, a port record and a per-file licence marker, whose format stays with DG018.)
